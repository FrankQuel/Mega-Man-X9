# ShadowMasterX5/MegamanX4: auditoría de reutilización en Unity 6

**Conclusión:** aporta un prototipo de movimiento, salto, animación y disparo para estudiar; requiere reconstrucción selectiva antes de integrarlo. No es una base completa ni una importación directa para el proyecto actual.

## Hallazgos priorizados

**P0 — entrada incompatible con la configuración actual.** PlayerMovement, PlayerJump, PlayerShotController y Weapon llaman `UnityEngine.Input.GetAxis/GetButton/GetKey`. El proyecto actual tiene únicamente el nuevo Input System activo. La compilación de esas API no garantiza que funcionen en ejecución con ese ajuste. Crear acciones Move/Jump/Fire y un adaptador; no cambiar silenciosamente todo el proyecto a «Both» para acomodar este prototipo.

**P0 — referencias de recursos no reproducibles al clonar.** El índice no conserva `.meta`, pero el controller usa GUID de clips, por ejemplo [m_Motion](https://github.com/ShadowMasterX5/MegamanX4/blob/c0d70c0a69fa626ee686498476e59a5941d4599f/Mega%20Man%20X4/Assets/Megaman%20X4/Animator/X/PlayerAnimatorController.controller#L1195). Unity generará GUID nuevos para los recursos sin metadatos: no se puede asumir que escena, prefabs y animaciones mantengan sus referencias. Reconstruirlas o reconectarlas con los recursos actuales; importar Library no sustituye ese trabajo.

**P1 — parámetro Shoot de tipo incorrecto.** [CheckShooting](https://github.com/ShadowMasterX5/MegamanX4/blob/c0d70c0a69fa626ee686498476e59a5941d4599f/Mega%20Man%20X4/Assets/Megaman%20X4/Scripts/PlayerAnimation.cs#L52) usa `SetBool("Shoot", ...)`; [controller: Shoot](https://github.com/ShadowMasterX5/MegamanX4/blob/c0d70c0a69fa626ee686498476e59a5941d4599f/Mega%20Man%20X4/Assets/Megaman%20X4/Animator/X/PlayerAnimatorController.controller#L23) declara Trigger (`m_Type: 9`). MegamanPlataform repite el error en su línea 121. Usar un trigger de disparo coherente. Cambiar simplemente el controller a bool también exigiría enviar false: el código solo escribe true cuando dispara.

**P1 — salida inmediata del disparo corriendo.** `xRunShooting` incluye una transición hacia `xIdle` sin condiciones y con `m_HasExitTime: 0`; el `m_ExitTime: 1` no la retrasa porque está desactivado. Puede abandonar la animación inmediatamente. Corregir condición o tiempo de salida. Evidencia: [transición](https://github.com/ShadowMasterX5/MegamanX4/blob/c0d70c0a69fa626ee686498476e59a5941d4599f/Mega%20Man%20X4/Assets/Megaman%20X4/Animator/X/PlayerAnimatorController.controller#L499), [estado que la utiliza](https://github.com/ShadowMasterX5/MegamanX4/blob/c0d70c0a69fa626ee686498476e59a5941d4599f/Mega%20Man%20X4/Assets/Megaman%20X4/Animator/X/PlayerAnimatorController.controller#L1178).

**P1 — daño sin implementar.** [OnTriggerEnter2D / MakeDamage](https://github.com/ShadowMasterX5/MegamanX4/blob/c0d70c0a69fa626ee686498476e59a5941d4599f/Mega%20Man%20X4/Assets/Megaman%20X4/Scripts/Shot.cs#L30) llama a un método virtual vacío, no identifica al receptor y desactiva el proyectil ante cualquier trigger; `damage` no se utiliza. [Shoot](https://github.com/ShadowMasterX5/MegamanX4/blob/c0d70c0a69fa626ee686498476e59a5941d4599f/Mega%20Man%20X4/Assets/Megaman%20X4/Scripts/Weapon.cs#L59) también tiene vacío el bloque de impacto. Rehacer interacción con un receptor de daño, propietario y filtros; los controllers Buster solo animan sprites.

**P1 — dirección y carga defectuosas en Weapon.** [raycast](https://github.com/ShadowMasterX5/MegamanX4/blob/c0d70c0a69fa626ee686498476e59a5941d4599f/Mega%20Man%20X4/Assets/Megaman%20X4/Scripts/Weapon.cs#L60) entrega la posición mundial de Direction como vector de dirección, en vez de la diferencia respecto a FirePoint. El disparo depende erróneamente de dónde esté el personaje. Además, `charge++` por Update mide fotogramas, no segundos: umbrales 30/60 cambian con FPS. Usar dirección normalizada y tiempo acumulado.

**P2 — perder control no detiene el cuerpo.** [FixedUpdate](https://github.com/ShadowMasterX5/MegamanX4/blob/c0d70c0a69fa626ee686498476e59a5941d4599f/Mega%20Man%20X4/Assets/Megaman%20X4/Scripts/PlayerMovement.cs#L19) omite Movement cuando `isControllable` es false o hay escalera, pero no borra la velocidad previa. Una desactivación por evento de animación puede dejar deriva horizontal. Definir explícitamente si cada estado frena, conserva impulso o deja actuar una entrada guionizada.

**P2 — pool y estado compartido.** [SetupShot](https://github.com/ShadowMasterX5/MegamanX4/blob/c0d70c0a69fa626ee686498476e59a5941d4599f/Mega%20Man%20X4/Assets/Megaman%20X4/Scripts/PlayerShotController.cs#L65) activa el objeto antes de colocar/configurar el disparo; OnEnable lee dirección de PlayerStats. Inyectar propietario, dirección y posición antes de activar. Validar `shotAmount >= 1`: con cero, ShotPooling consulta índice 0 de un array vacío. Si varios actores comparten el mismo asset PlayerStats, también comparten sus banderas mutables y orientación; usar estado individual.

**P2 — variantes antiguas no intercambiables.** Plataform2DCharacter declara `PlatformerCharacter2D`, distinto del nombre del archivo; debe regularizarse para su uso como MonoBehaviour. Sus líneas 52–53 disparan Shoot cada FixedUpdate aunque no haya disparo, y la 82 activa isMoving sin rama que lo desactive. Hay un archivo homónimo en Standard Assets, pero no se leyó su cuerpo: la colisión de tipo es un riesgo, no un error de compilación verificado. `MegamanPlataform.cs:66` llama Set sobre una copia de localScale y no asigna el resultado; no cambia la escala del Transform.

## Controller, ausencias y adaptación concreta

El controller contiene quince estados y cinco máquinas, incluida Base Layer. Hay Jump/Shoot como triggers; movimiento, suelo, aterrizaje y crouch como bools; vSpeed como float. `xCrouch` no tiene transiciones y no se encontró condición Crouch que lo alcance. Las banderas de escalera no equivalen a subirla: CheckLadder está comentado y esos triggers no reciben una implementación modular. No se verificaron los Animation Events de los clips; los métodos EnableControl/DisableControl por sí solos no prueban una entrada completa.

Los once scripts no aportan combate terminado, vida actual/curación/muerte, HUD por jugador, checkpoints, guardado, IA de jefe ni la orquestación READY→entrada→Idle. Stats solo ofrece maxHealth limitado por Inspector a 0–20 y banderas; no sustituye nuestro CharacterHealth de 28/48.

La integración recomendada es reescribir un único motor con Input Actions, capturar botones en Update y aplicar física en FixedUpdate; estado separado por actor; adaptador hacia los nombres de clips actuales; proyectiles preparados antes de activación y daño real. Conservar la biblioteca, HUD y secuencia de presentación existentes. Después verificar en una escena aislada dirección izquierda/derecha, parada al bloquear control, altura de salto, disparo en suelo/aire, pausa y dos actores independientes a distintas tasas de fotogramas. Esas pruebas de ejecución todavía no se realizaron en esta auditoría.
